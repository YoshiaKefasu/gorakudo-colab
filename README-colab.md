# GoRakuDo ComfyUI on Colab（README-colab）

`GoRakuDo_ComfyUI_Colab.ipynb` の手順書。**G4（RTX PRO 6000 Blackwell 96GB）+ bf16フル精度での運用を主経路**とする。
T4 / L4 / A100 はフォールバック（int8自動切替）として後段にまとめた。

> ※ Colab実機での実行は未検証。JSON構造・構文・モデルURL到達性のみ検証済み。
> 数値はすべて**推定**。料金は変動が大きいので実行前に公式ページで確認すること。

## G4での使い方（3ステップ）

1. ノートブックをColabにアップロード → ランタイムを **G4 GPU** にする
2. セル1〜5を上から実行（GPU確認→ComfyUI取得→モデルDL約32GB→ワークフロー書出→起動+公開URL）
3. セル6で1枚生成（`RESOLUTION` を1024/1280/1536/2048から選択）、edit/inpaintを使う場合のみセル6.5で参照画像を登録、セル7でバッチ連番生成→zip取得

G4（96GB）では **bf16フル精度・1536〜2048px・同一プロンプト10枚連番でも1〜2分**が目安。
GUI（cloudflared公開URL）も使えるが、量産はセル6/7のAPI経路が速い。

## GPU別 見積り表（すべて推定）

前提: 1024²・Pruna 8step・CFG 1・ネガティブ空。RTX 2060（ローカル）実測79秒/int8を基準に
メモリ帯域・世代差から概算。G4の8〜10秒は bf16 での推定値。

| GPU | VRAM | モード | 1枚あたり秒数（推定） | 1時間あたり枚数 | 1枚あたりコスト目安（推定） | 使うべき場面 |
|---|---|---|---|---|---|---|
| T4 | 15GB | int8 + lowvram | 約85秒 | 約40枚 | 約$0.005 | お試し・少量・安く |
| L4 | 22.5GB | int8 | 約35秒 | 約100枚 | 約$0.004 | コスパ中量産 |
| A100 40GB | 40GB | int8 | 約15秒 | 約240枚 | 約$0.006 | 高速中量産 |
| **G4 RTX PRO 6000** | **96GB** | **bf16（フル精度）** | **約8〜10秒** | **約360〜450枚** | **約$0.01** | **短時間で大量・高解像度** |

コストの仮定（推定・要確認）: Colabは100CU=$9.99。T4≈2CU/h、L4≈時間単価$0.4/h相当、
A100≈14CU/h、G4はGCE換算で時間単価 数$/h級（構成依存・変動大）。
1枚単価はどのGPUでも大差ない（速いGPUは時間単価も高い）が、**G4は「1時間で数百枚」を
短時間セッションで回せる**点が強み。長時間ダラダラ回すと高くつくので、
プロンプトリストを用意してから一気に回す使い方が向く。

## G4の強み（96GBで何が変わるか）

- **bf16フル精度**（量子化ロスなし）: int8版（7.26GB）の代わりにbf16版（14.23GB）を使える。
  TEもbf16版（17.53GB）推奨。VRAM48GB未満では自動でint8にフォールバックする。
- **1536〜2048pxも実用的**: 解像度プリセットはセル6/7の `RESOLUTION` で切替（1024/1280/1536/2048）。
- **バッチ生成可**: セル7の `SAME_PROMPT_N` に枚数を入れると同一プロンプトをseed連番で量産。
- 一方で**時間単価が高い**ので「短時間で大量」型に向く。放置セッションは避ける。

## セッションあたりの所要

- モデルDL: bf16経路で **約32〜33GB**（UNET 14.23 + TE-bf16 17.53 + VAE 0.68 + LoRA 0.32）、
  int8経路で **約17.6GB**。Colabのディスク（無料枠でも100GB級）で問題なし。
  初回DLは数分〜十数分（回線依存）。2回目以降はスキップ判定ありだが、
  Driveを使わない運用では**セッション切断で消える**ため毎回DLし直しになる点に注意。（DLはcurl/wget）
- 生成: 上の表の通り。G4+bf16+1024²で1枚8〜10秒（推定）。

## Driveを使わない運用 vs 使う場合の差分

- 既定（Driveなし）: 毎セッション約32GBをDLし直す。成果物は `files.download` で都度落とす。
  シンプルで権限トラブルがない。
- Driveを使う場合の差分: `models/` をDriveにマウントして永続化すればDLは初回のみ。
  代わりにマウント処理・I/Oの遅さ・容量圧迫（32GB）と引き換え。やるならセル3のDL先を
  `/content/drive/MyDrive/...` に変え、ComfyUI起動時に `--extra-model-paths` 相当の設定を追加する
  （本ノートブックには含めない・必要になったら追加）。

## つまずきポイント

1. **`QwenImage21Cache` ノードを入れない**: 新しいメモリ管理（aimdo malloc graph）と相性が悪く、
   `RuntimeError: aimdo memory compile error` が出ることがある。埋め込みワークフローは除去済み。
   GUIで自作WFを使う場合もこのノードは追加しないこと。
2. **`--lowvram` は付けても付けなくてもほぼ変わらない**: このComfyUIは dynamic VRAM が既定で有効なため
   `--lowvram` は実質ノーオペ。セル1がVRAMから自動選択するが、G4/A100では空・T4等では付与のまま動く。
3. **cloudflaredのURLが出ない**: トンネル確立に1〜2分かかることがある。ログを見て待つ。
   何度も失敗する場合はランタイム再起動→セル5から再実行。
4. **モデル名の一致**: ワークフロー内の `unet_name` / `clip_name` / `vae_name` / `lora_name` と
   DLしたファイル名が1文字でも違うとロード失敗。セル4のTEフォールバック差し替え以外は
   ファイル名を変えないこと。bf16系=int8系で `filename_prefix` のみ変えている。
5. **T2I/Edit/Inpaintの使い分け**: T2Iはテキストのみ、Editは参照画像（セル6.5で登録）、
   Inpaintはベース画像+マスク。セル4が書く `workflows/`（API形式）はGUIから読めない。
   GUIで使うJSONは `user/default/workflows/`（セル4bの Main Workflow）のみ。
6. **アイドル切断**: セル8はおまじない程度。長バッチは放置せず、終わったら即ダウンロードする。
## Main Workflow（自分のワークフロー）をColabで使う

**方法A: ノートブックに同梱済み（推奨）**
`セル4b` を実行すると、ローカルの `GoRakuDo Main Workflow` が
`/content/ComfyUI/user/default/workflows/` に書き出されます。
ColabのGUI（cloudflaredのURL）を開き、**左サイドバーの「ワークフロー」一覧**から選ぶだけ。

- この同梱版は **`QwenImage21Cache` を2つとも除去して配線し直してあります**
  （`aimdo memory compile error` を避けるため）
- モデル名は **そのランタイムに合わせて自動で差し替え**（bf16 / int8）
- ローカルの最新版を反映したい時は、手元の
  `D:\OSS_ProgramFiles\ComfyUI\user\default\workflows\GoRakuDo Main Workflow.json`
  を `tools/colab/GoRakuDo_Main_Workflow_cachefree.json` として作り直す。
  （Note: **ipynbが正本。生成スクリプト（`build_colab_nb.py`/`fix_nb.py`）は参考用で再生成しない**）

**方法B: GUIにドラッグ＆ドロップ**
公開URLのComfyUI画面に、手元の `.json` を**そのままドロップ**しても読み込めます。
ただし**そのままでは `QwenImage21Cache` が入っている**ので、
読み込んだら**Cacheノードを2つ削除**してください（消すだけでOK。配線はLoRA→サンプラーに繋ぎ直す）。

**方法C: GUIを使わずAPIで回す**
`セル6` に自分のプロンプトを入れて実行するのが一番速いです（画像は自動でローカルに落ちます）。

## つまずきポイント（追記）
- `AttributeError: 'CompletedProcess' object has no attribute 'text'`
  → 修正済み（`.stdout` を読む）
- `if` の中に `!git clone` / `!wget` を書くと環境によって壊れる → `subprocess.run` に置換済み

## セル6.5: 参照画像の登録（edit/inpaintを使う場合のみ）

1. セル4→セル5の順に実行して `workflows/` とComfyUIの起動を済ませてからセル6.5を実行
2. ファイル選択ダイアログで画像を1〜2枚アップロード（1枚なら参照・ベース兼用、2枚なら1枚目=参照・2枚目=ベース）
3. `updated edit_*_api.json / inpaint_*_api.json` と出れば完了。**セル6/7はT2I専用。edit/inpaintは（参照を置換したAPI JSONを）GUIまたは別途APIで送る**

`REPLACE_ME_REF.png` はedit系（`edit_*_api.json`）の参照画像の仮名、`REPLACE_ME_BASE.png` は
inpaint系（`inpaint_*_api.json`）のベース画像の仮名。セル6.5が実ファイル名に置換する。
T2I系は参照画像を使わないので対象外。画像なしで実行したらスキップ表示のまま次に進める。
**2回目以降のアップロードは、既に置換済みのJSONには反映されない**（`REPLACE_ME_*` が残っていないとスキップ）。

## 公開URLのセキュリティ注意

- trycloudflareの公開URLは**認証なしでComfyUIのAPIを叩ける**。他人にURLを渡さないこと
- 生成が終わったら必ずランタイムを停止（Colabメニュー → ランタイム → セッションの停止）
- URLはセッションごとに変わる。使い回さず毎回セル5の出力から開くこと## 公開URLが開けなくなったとき / セッションが切れたとき

**症状**: ブラウザで `https://xxxxx.trycloudflare.com` を開くと **403**（Cloudflareのエラーページ）／
または「開けなくなった」。

**なぜ起きるか**
- Colab の**ランタイムが切れると、その上の cloudflared も死ぬ** → URLが無効になる（403はCloudflare側の応答）
- ランタイムが生きていても、**cloudflared だけ落ちる**ことがある（自動更新・ネットワーク瞬断など）

**対処（セル5に「自動復帰」を入れてあります）**
- `セル5` は起動後に **ウォッチドッグ**を走らせる。cloudflared が落ちると**自動で作り直し、新しいURLをログに表示**する
  → 出力に `[watchdog] 新しい公開URL: https://…` が出たら、そのURLを開き直す
- セッション自体が切れた場合は **セル1〜5 を再実行**（新しいURLが発行される。モデルDLはスキップされ数分で復帰）

**アイドル切断を減らす（セル8）**
- `セル8` は60秒ごとに Colab の接続ボタンを押して**アイドル判定をリセット**する
- **タブを閉じる／バックグラウンドに回すと効果が落ちる**ので、開いたままにする
- **Colabには約12時間のセッション上限**があるため、放置での維持には限界がある

**GUIに依存しないのが一番確実**
- 画像生成そのものは **セル6/7（API経路）**で完結する。トンネルが死んでも生成は続けられる
- GUIが必要なのは「ワークフローを手で触りたいとき」だけ。無理ならローカルのComfyUIを使う

## セル9: 監視ループ（アクティブ・Verbose）

**最後に実行する監視セル**。走らせている間は他セルを実行できない（カーネルを占有する）ので、様子を見たいときだけ使う。

- **cloudflared の生ログを全部表示**（`[cf] ...`）
- **15秒ごとに状態1行**: `[HH:MM:SS] ComfyUI OK | VRAM x/y GB | 実行中 n / 待機 m | トンネル 生存 | https://...`
- **トンネルが落ちたら自動で作り直して新しいURLを表示**
- **ComfyUI が無応答なら自動で再起動**
- 既定は **30分で自動終了**（`LOOP_SECONDS = 0` にすると止めるまで回り続ける）
- ■（停止）で抜けても、**セル5のウォッチドッグ（スレッド）は生き続ける**ので監視は継続される

**注意**: ループ中は生成セル（6/7）を実行できない。生成したいときは ■ で止める。

## セル5 は「回りっぱなし」になりました（Verboseループ内蔵）

Colabは**操作がないとセッションを落とす**ため、セル5 はURLを出したあと**そのまま監視ループに入ります**（既定）。

- 表示され続けるもの: `[cf]` cloudflaredの生ログ／15秒ごとの状態行
  （`ComfyUI OK | VRAM x/y GB | 実行中 n / 待機 m | トンネル 生存 | https://...`）
- **■（停止）で抜けられる**。抜けても ComfyUI と トンネルは別プロセスなので**動き続ける**
- ループ中は他のセルを実行できないが、**ローカル・ブリッジ（tools/remote-bridge.py）経由なら生成できる**
- このカーネルからセル6/7 を動かしたいときだけ先頭の `STAY_ALIVE = False` にして、
  代わりに**セル9**を実行して維持する

# GoRakuDo ComfyUI on Colab（README-colab）

`GoRakuDo_ComfyUI_Colab.ipynb` の手順書。**G4（RTX PRO 6000 Blackwell 96GB）+ bf16フル精度での運用を主経路**とする。
T4 / L4 / A100 はフォールバック（int8自動切替）として後段にまとめた。

> ※ Colab実機での実行は未検証。JSON構造・構文・モデルURL到達性のみ検証済み。
> 数値はすべて**推定**。料金は変動が大きいので実行前に公式ページで確認すること。

## G4での使い方（3ステップ）

1. ノートブックをColabにアップロード → ランタイムを **G4 GPU** にする
2. セル1〜5を上から実行（GPU確認→ComfyUI取得→モデルDL約32GB→ワークフロー書出→起動+公開URL）
3. セル6で1枚生成（`RESOLUTION` を1024/1280/1536/2048から選択）、セル7でバッチ連番生成→zip取得

G4（96GB）では **bf16フル精度・1536〜2048px・同一プロンプト10枚連番でも1〜2分**が目安。
GUI（cloudflared公開URL）も使えるが、量産はセル6/7のAPI経路が速い。

## GPU別 見積り表（すべて推定）

前提: 1024²・Pruna 8step・CFG 1・ネガティブ空。RTX 2060（ローカル）実測79秒/int8を基準に
メモリ帯域・世代差から概算。G4の8〜10秒は bf16 での推定値。

| GPU | VRAM | モード | 1枚あたり秒数（推定） | 1時間あたり枚数 | 1枚あたりコスト目安（推定） | 使うべき場面 |
|---|---|---|---|---|---|---|
| T4 | 15GB | int8 + lowvram | 約85秒 | 約40枚 | 約$0.005 | お試し・少量・安く |
| L4 | 22.5GB | int8 | 約35秒 | 約100枚 | 約$0.004 | コスパ中量産 |
| A100 40GB | 40GB | int8 | 約15秒 | 約240枚 | 約$0.006 | 高速中量産 |
| **G4 RTX PRO 6000** | **96GB** | **bf16（フル精度）** | **約8〜10秒** | **約360〜450枚** | **約$0.01** | **短時間で大量・高解像度** |

コストの仮定（推定・要確認）: Colabは100CU=$9.99。T4≈2CU/h、L4≈時間単価$0.4/h相当、
A100≈14CU/h、G4はGCE換算で時間単価 数$/h級（構成依存・変動大）。
1枚単価はどのGPUでも大差ない（速いGPUは時間単価も高い）が、**G4は「1時間で数百枚」を
短時間セッションで回せる**点が強み。長時間ダラダラ回すと高くつくので、
プロンプトリストを用意してから一気に回す使い方が向く。

## G4の強み（96GBで何が変わるか）

- **bf16フル精度**（量子化ロスなし）: int8版（7.26GB）の代わりにbf16版（14.23GB）を使える。
  TEもbf16版（17.53GB）推奨。VRAM48GB未満では自動でint8にフォールバックする。
- **1536〜2048pxも実用的**: 解像度プリセットはセル6/7の `RESOLUTION` で切替（1024/1280/1536/2048）。
- **バッチ生成可**: セル7の `SAME_PROMPT_N` に枚数を入れると同一プロンプトをseed連番で量産。
- 一方で**時間単価が高い**ので「短時間で大量」型に向く。放置セッションは避ける。

## セッションあたりの所要

- モデルDL: bf16経路で **約32〜33GB**（UNET 14.23 + TE-bf16 17.53 + VAE 0.68 + LoRA 0.32）、
  int8経路で **約17.6GB**。Colabのディスク（無料枠でも100GB級）で問題なし。
  初回DLは `hf_transfer` 有効で数分〜十数分（回線依存）。2回目以降はスキップ判定ありだが、
  Driveを使わない運用では**セッション切断で消える**ため毎回DLし直しになる点に注意。
- 生成: 上の表の通り。G4+bf16+1024²で1枚8〜10秒（推定）。

## Driveを使わない運用 vs 使う場合の差分

- 既定（Driveなし）: 毎セッション約32GBをDLし直す。成果物は `files.download` で都度落とす。
  シンプルで権限トラブルがない。
- Driveを使う場合の差分: `models/` をDriveにマウントして永続化すればDLは初回のみ。
  代わりにマウント処理・I/Oの遅さ・容量圧迫（32GB）と引き換え。やるならセル3のDL先を
  `/content/drive/MyDrive/...` に変え、ComfyUI起動時に `--extra-model-paths` 相当の設定を追加する
  （本ノートブックには含めない・必要になったら追加）。

## つまずきポイント

1. **`QwenImage21Cache` ノードを入れない**: 新しいメモリ管理（aimdo malloc graph）と相性が悪く、
   `RuntimeError: aimdo memory compile error` が出ることがある。埋め込みワークフローは除去済み。
   GUIで自作WFを使う場合もこのノードは追加しないこと。
2. **`--lowvram` の付け忘れ/付けすぎ**: 20GB未満（T4等）では必須、G4/A100では付けない。
   セル1がVRAMから自動選択する。逆にするとOOMか無駄な低速化になる。
3. **cloudflaredのURLが出ない**: トンネル確立に1〜2分かかることがある。ログを見て待つ。
   何度も失敗する場合はランタイム再起動→セル5から再実行。
4. **モデル名の一致**: ワークフロー内の `unet_name` / `clip_name` / `vae_name` / `lora_name` と
   DLしたファイル名が1文字でも違うとロード失敗。セル4のTEフォールバック差し替え以外は
   ファイル名を変えないこと。bf16系=int8系で `filename_prefix` のみ変えている。
5. **T2I/Edit/Inpaintの使い分け**: T2Iはテキストのみ、Editは参照画像（`LoadImage`に参照を入れる）、
   Inpaintはベース画像+マスク。GUIで使う場合は `workflows/` の対応JSONを読み込む。
6. **アイドル切断**: セル8はおまじない程度。長バッチは放置せず、終わったら即ダウンロードする。
## Main Workflow（自分のワークフロー）をColabで使う

**方法A: ノートブックに同梱済み（推奨）**
`セル4b` を実行すると、ローカルの `GoRakuDo Main Workflow` が
`/content/ComfyUI/user/default/workflows/` に書き出されます。
ColabのGUI（cloudflaredのURL）を開き、**左サイドバーの「ワークフロー」一覧**から選ぶだけ。

- この同梱版は **`QwenImage21Cache` を2つとも除去して配線し直してあります**
  （`aimdo memory compile error` を避けるため）
- モデル名は **そのランタイムに合わせて自動で差し替え**（bf16 / int8）
- ローカルの最新版を反映したい時は、手元の
  `D:\OSS_ProgramFiles\ComfyUI\user\default\workflows\GoRakuDo Main Workflow.json`
  を `tools/colab/GoRakuDo_Main_Workflow_cachefree.json` として作り直し、
  `python fix_nb.py` を実行（ノートブックに再埋め込み）

**方法B: GUIにドラッグ＆ドロップ**
公開URLのComfyUI画面に、手元の `.json` を**そのままドロップ**しても読み込めます。
ただし**そのままでは `QwenImage21Cache` が入っている**ので、
読み込んだら**Cacheノードを2つ削除**してください（消すだけでOK。配線はLoRA→サンプラーに繋ぎ直す）。

**方法C: GUIを使わずAPIで回す**
`セル6` に自分のプロンプトを入れて実行するのが一番速いです（画像は自動でローカルに落ちます）。
